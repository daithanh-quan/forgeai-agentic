# Phase 16.6 — Quantified Context Proof: Design

## Problem

ForgeAI có hai "wow moment" đã được xác nhận:

1. **`try` output** — người dùng thấy ngay file nào sẽ được chọn mà không cần install
2. **Tiết kiệm token** — context nhỏ hơn đáng kể so với gửi cả repo

Vấn đề: cả hai moment này hiện **không có con số cụ thể**. `try` hiển thị `~42.1 KB selected (raw source)` nhưng không cho thấy 42 KB đó so với bao nhiêu và bao nhiêu phần trăm đã bị loại. `--compile-context` hiển thị `estimated tokens 4821/6000` nhưng không cho biết scope đầu vào.

Kết quả: người dùng không cảm nhận được giá trị thực sự; không có con số để share.

## Goal

Làm cho hai wow moment trở nên **có thể đo lường và share** bằng cách thêm:

1. **Exclusion metrics** vào `try` output — tỷ lệ indexed source bị loại khỏi context
2. **Source scope summary** vào `--compile-context` file-output mode — selected source / indexed source
3. **State-aware CTA** trong `try` — hướng dẫn next step dựa trên trạng thái thật của `.ai/`

## Metric Scope Clarification

**`try` và `--compile-context` đo file-level bytes, không phải excerpt bytes.**

- `selectedSourceBytes` = tổng kích thước file của các file được select (không phải excerpts)
- `totalSourceBytes` = tổng kích thước file của tất cả nodes trong dep graph
- Dep graph chỉ index extensions có parser (TS/JS/Python/Go), bỏ `.d.ts` và ignored dirs — do đó dùng **"indexed source"**, không dùng "repo"
- `estimated tokens` thể hiện kích thước ước tính của **toàn bộ compiled artifact** (selection metadata, rules, diagnostics, excerpts — không phải excerpts-only). Hai metrics bổ sung nhau nhưng đo hai thứ khác nhau.

Hai thứ này bổ sung nhau:
- `Selected ~42.1 KB of ~380.4 KB indexed source (89% excluded)` → cho biết scope đầu vào (file bytes)
- `estimated tokens 4821/6000` → cho biết kích thước artifact đã compile gửi lên model

## Non-Goals

- Provider-accurate token-savings percentage claims (Principle #5 cấm claim savings khi không có provider usage data; local estimation thì không bị cấm)
- Clipboard copy
- GitHub Action template
- `--report` cumulative savings (cần run record schema changes — defer)
- Phase 16.2c Rust parser (vẫn planned, ship độc lập)

## Feature 2: Source Scope Summary trong `--compile-context` (file-output mode only)

### Scope constraint

`runCompileContext` (context-compiler.ts) returns early tại line 604–607 khi không có `--output`:

```typescript
if (!outputArg) {
  process.stdout.write(json);
  return;                     // ← console.log không bao giờ chạy sau đây

```

Source scope summary **chỉ xuất hiện trong file-output mode** (`--output <json>` được cung cấp). Behavior trong JSON stdout mode không thay đổi. Spec không support stderr alternative cho JSON stdout mode.

```
✓  source scope   ~42.1 KB of ~380.4 KB indexed source  (89% excluded)
```

### Implementation

Trong `runCompileContext()`, sau khi write artifacts và trước `estimated tokens` log:

```typescript
const selectedPaths = new Set(artifact.selection.files.map((f) => f.path));
const selectedSourceBytes = dependencyGraph!.nodes
  .filter((n) => selectedPaths.has(n.path))
```

`dependencyGraph` đã được read và validated trước line 602 — không cần re-read.

### `formatBytes` — shared utility

`formatBytes` hiện là private trong `try.ts`. Cần dùng ở cả `try.ts` và `context-compiler.ts` → extract vào `bin/lib/utils.ts`:

```typescript
export function formatBytes(n: number): string {
  if (n >= 1024 * 1024) return `${(n / (1024 * 1024)).toFixed(1)} MB`;
  if (n >= 1024) return `${(n / 1024).toFixed(1)} KB`;
  return `${n} bytes`;
}
```

`try.ts` xóa local copy và import từ `utils.js`.

## Feature 3: State-Aware CTA trong `try`

### Six states

| State | Condition | Recovery command |
|-------|-----------|-----------------|
| `uninitialized` | `graph.json` không tồn tại | `--profile auto` |
| `graph-unreadable` | `graph.json` tồn tại nhưng read fail (EACCES/EIO) | check file permissions |
| `needs-reinit` | `graph.json` readable nhưng không parse được (JSON malformed) | `--repair-codegraph` |
| `needs-graph` | `graph.json` valid, dep graph file không tồn tại | `--refresh-codegraph` |
| `needs-refresh` | Cả hai file tồn tại nhưng `checkDependencyGraphHealth` non-ok | `--refresh-codegraph` |
| `ready` | `graph.json` valid, dep graph health `ok` | `--compile-context` |

**Tại sao tách `graph-unreadable` khỏi `needs-reinit`:** `--repair-codegraph` từ chối repair khi `readFileSync` fail (exit 1). Nếu CTA cho read-fail là `--repair-codegraph`, user chạy command đó vẫn bị lỗi — hướng dẫn sai. `graph-unreadable` trỏ đến nguyên nhân thực (permission/IO) và đề nghị kiểm tra permission thay vì chạy repair.

### `--repair-codegraph` targeted CLI command (new feature)

**Tại sao không dùng shell backup + `--upgrade`:**
- `mv`/`mktemp`/command substitution không portable (fail trên Windows/PowerShell)
- `--upgrade` cần biết manifest state để chọn đúng flag → phức tạp và có thể thay đổi profile ngoài ý muốn

**`--repair-codegraph` behavior** (thêm vào `bin/lib/init.ts`):
1. Nếu `graph.json` không tồn tại → báo lỗi "nothing to repair", exit 1
2. Read `graph.json` bằng `fs.readFileSync` — nếu read fail (EACCES, EIO, v.v.) → báo operational error, exit 1, **không repair**
3. Parse content bằng `JSON.parse` — nếu parse thành công → báo "already valid JSON — nothing to repair", exit 0 (refuse to repair a parse-valid graph). Chỉ khi parse fail mới tiến hành repair
4. **Write ignore rules (best-effort)**: write/update `.ai/codegraph/.gitignore` để chứa `graph.json.backup.*` và `graph.json.tmp.*` trước khi tạo bất kỳ file nào. Nếu write thất bại → in warning ra stderr và tiếp tục (non-fatal); người dùng nên kiểm tra `git status` trước khi commit
5. Backup: `fs.copyFileSync(original, backup, COPYFILE_EXCL)` — no-clobber; retry với new `crypto.randomBytes(4).toString('hex')` suffix nếu EEXIST. Tối đa 10 lần; sau đó throw "could not create unique backup path after 10 attempts"
6. Copy template sang temp sibling bằng `fs.copyFileSync(template, tmp, COPYFILE_EXCL)` — no-clobber + retry suffix. Tối đa 10 lần; sau đó throw "could not create unique tmp path after 10 attempts"
7. Parse-validate temp (`JSON.parse(fs.readFileSync(tmp))`) — nếu invalid thì cleanup tmp, giữ nguyên canonical, exit 1 với "template graph.json is not valid JSON"
8. Atomic rename: `fs.renameSync(tmp, graphPath)` — overwrites canonical only after backup, tmp, and validation all confirmed
9. Cleanup temp nếu bất kỳ bước nào từ 6–8 fail; original vẫn ở canonical path (không bị thay đổi trước step 8). Backup từ step 5 có thể còn lại — đây là intentional: backup là recovery artifact và không được xóa khi repair fail. Backup **thường** được ignore bởi `.gitignore` (repair command cố gắng ghi rules ở step 4 trước khi tạo backup); nếu step 4 in warning, backup có thể hiện trong `git status` và người dùng nên kiểm tra trước khi commit.
10. Log: `repaired .ai/codegraph/graph.json (backup: <backup-path>)`
11. Không đụng đến manifest, profiles, dependency graph (`dependency-graph.json`), hay các file harness khác; chỉ sửa canonical `graph.json`, `.ai/codegraph/.gitignore`, và tạo backup/temp trong cùng thư mục

**Tại sao flow này an toàn:**
- Steps 2–3 (read trước parse): lỗi đọc file (EACCES, EIO) → exit ngay, không repair. Chỉ lỗi JSON mới trigger repair — tránh thay graph hợp lệ khi filesystem có vấn đề tạm thời
- Step 4 (gitignore best-effort): attempt trước backup để minimize window; nếu fail, warning được in, artifacts vẫn được tạo nhưng không có guarantee chúng được ignore
- Step 5 (`COPYFILE_EXCL`): backup không bao giờ overwrite file existing (no-clobber + retry)
- Step 6 (`COPYFILE_EXCL` cho tmp): tránh ghi đè temp file còn sót từ process crash trước
- Steps 6–9: original ở canonical path đến tận step 8 (rename tmp → canonical). Nếu copy template fail, validation fail hoặc rename fail, tmp được cleanup và original canonical remains intact

```typescript
import crypto from 'node:crypto';

interface RepairCodeGraphOptions {
  graphPath?: string;
  templateGraphPath?: string;
  gitignorePath?: string;       // defaults to path.join(path.dirname(graphPath), '.gitignore')
  randomSuffix?: () => string;
}

export function runRepairCodeGraph({
  graphPath = path.join(root, '.ai', 'codegraph', 'graph.json'),
  templateGraphPath = path.join(templateDir, '.ai', 'codegraph', 'graph.json'),
  gitignorePath = path.join(path.dirname(graphPath), '.gitignore'),
  randomSuffix = () => crypto.randomBytes(4).toString('hex'),
}: RepairCodeGraphOptions = {}): void {
  if (!fs.existsSync(graphPath)) {
    process.stderr.write('Error: .ai/codegraph/graph.json not found — nothing to repair.\n');
    process.exitCode = 1;
    return;
  }
  // Step 1: read (operational errors exit immediately — do not repair)
  let content: string;
  try {
    content = fs.readFileSync(graphPath, 'utf-8');
  } catch (err) {
    process.stderr.write(`Error: could not read .ai/codegraph/graph.json (${getErrorMessage(err)}).\n`);
    process.exitCode = 1;
    return;
  }
  // Step 2: parse (valid JSON → refuse repair; parse failure → proceed)
  try {
    JSON.parse(content);
    console.log(formatStatus('ok', '.ai/codegraph/graph.json is already valid JSON — nothing to repair.'));
    return;
  } catch { /* JSON parse failed — proceed with repair */ }

  // Step 3: write ignore rules (best-effort — non-fatal if write fails)
  const requiredPatterns = ['graph.json.backup.*', 'graph.json.tmp.*'];
  try {
    const existing = fs.existsSync(gitignorePath) ? fs.readFileSync(gitignorePath, 'utf-8') : '';
    const existingLines = new Set(existing.split('\n').map((l) => l.trim()));
    const missing = requiredPatterns.filter((p) => !existingLines.has(p));
    if (missing.length > 0) {
      const sep = existing.length > 0 && !existing.endsWith('\n') ? '\n' : '';
      fs.writeFileSync(gitignorePath, existing + sep + missing.join('\n') + '\n');
    }
  } catch (err) {
    process.stderr.write(`Warning: could not write .gitignore (${getErrorMessage(err)}). Check git status before committing.\n`);
  }

  const MAX_RETRY = 10;
  let tmpPath: string | undefined;
  try {
    // Step 1: no-clobber backup (bounded retry on suffix collision)
    let backupPath: string;
    for (let attempt = 0; ; attempt++) {
      if (attempt >= MAX_RETRY) throw new Error('could not create unique backup path after 10 attempts');
      backupPath = `${graphPath}.backup.${randomSuffix()}`;
      try {
        fs.copyFileSync(graphPath, backupPath, fs.constants.COPYFILE_EXCL);
        break;
      } catch (err: unknown) {
        if ((err as NodeJS.ErrnoException).code !== 'EEXIST') throw err;
      }
    }

    // Step 2: copy template to unique tmp (bounded retry on suffix collision)
    for (let attempt = 0; ; attempt++) {
      if (attempt >= MAX_RETRY) throw new Error('could not create unique tmp path after 10 attempts');
      const candidate = `${graphPath}.tmp.${randomSuffix()}`;
      try {
        fs.copyFileSync(templateGraphPath, candidate, fs.constants.COPYFILE_EXCL);
        tmpPath = candidate;
        break;
      } catch (err: unknown) {
        if ((err as NodeJS.ErrnoException).code !== 'EEXIST') throw err;
      }
    }
    // Step 3: validate template before overwriting canonical (read and parse separately)
    let tmpContent: string;
    try {
      tmpContent = fs.readFileSync(tmpPath, 'utf-8');
    } catch (err) {
      throw new Error(`could not read template copy (${getErrorMessage(err)})`);
    }
    try {
      JSON.parse(tmpContent);
    } catch {
      throw new Error('template graph.json is not valid JSON — cannot repair');
    }
    // Step 4: atomic rename → canonical (only reached after backup + tmp + validation all confirmed)
    fs.renameSync(tmpPath, graphPath);
    tmpPath = undefined;  // rename succeeded — no cleanup needed

    console.log(formatStatus('ok', `repaired .ai/codegraph/graph.json (backup: ${path.relative(root, backupPath)})`));
  } catch (err) {
    if (tmpPath) { try { fs.unlinkSync(tmpPath); } catch { /* ignore */ } }
    process.stderr.write(`Error: codegraph repair failed (${getErrorMessage(err)}).\n`);
    process.exitCode = 1;
  }
}
```

`crypto` đã available từ Node.js built-in (không cần npm dependency). `templateDir` và `root` đã import từ context.js. `formatStatus`, `getErrorMessage` từ utils.js.

**Tại sao injectable options:**
- `templateGraphPath`: unit tests inject path không tồn tại (template missing) hoặc path chứa malformed JSON (template invalid) — không cần xóa package assets
- `gitignorePath`: unit tests inject path với parent directory không tồn tại (ENOENT trên writeFileSync, stable cross-platform) để test warning path
- `randomSuffix`: unit tests kiểm soát collision retry bằng cách return same value N lần rồi mới đổi
- E2E test CLI command (`npx ... --repair-codegraph`) dùng real paths, không inject gì, không mutate template

**Backup lifecycle:** Repair command cố gắng ghi `.ai/codegraph/.gitignore` với `graph.json.backup.*` và `graph.json.tmp.*` trước khi tạo bất kỳ file nào. Nếu thành công, leftover files sẽ không bị commit; nếu thất bại, warning được in và người dùng cần kiểm tra `git status`. Pattern này cũng được ghi bởi `maintainCodeGraphGitignore()` (private helper trong `init.ts`) khi `runInit()` chạy — cả fresh install lẫn `--upgrade` đều gọi nó sau `copyRecursive` — nên không cần ship `.ai/codegraph/.gitignore` dưới dạng template file (npm sẽ loại bỏ file `.gitignore` khỏi package artifact).

**Schema-invalid-but-parseable graphs không cần riêng state `needs-reinit`**: Cả `readCuratedCodeGraph` và `tryReadCuratedCodeGraph` đều dùng `parseCuratedCodeGraph` + `normalizeCuratedGraph`, nên `{"nodes": [null], ...}` được normalize an toàn — không crash, CTA `ready` là đúng.

### `CtaState` type

```typescript
export type CtaState = 'uninitialized' | 'graph-unreadable' | 'needs-reinit' | 'needs-graph' | 'needs-refresh' | 'ready';
```

### `detectCtaState` function

Internal, không export (chỉ `runTry()` gọi). Read và parse được tách riêng để phân biệt permission/IO errors khỏi JSON corruption:

```typescript
import { DEPENDENCY_GRAPH_PATH, readDependencyGraph, checkDependencyGraphHealth } from './dependency-graph.js';

function detectCtaState(projectRoot: string): CtaState {
  const curatedGraphFile = path.join(projectRoot, '.ai', 'codegraph', 'graph.json');
  const depGraphFile = path.join(projectRoot, DEPENDENCY_GRAPH_PATH);

  // 1. Curated graph missing → not initialized
  if (!fs.existsSync(curatedGraphFile)) return 'uninitialized';

  // 2. Read and parse separately — EACCES/EIO is not JSON corruption
  // Schema-invalid-but-parseable graphs are handled by normalizeCuratedGraph at
  // the readCuratedCodeGraph layer — detectCtaState only catches read/parse failures.
  let content: string;
  try {
    content = fs.readFileSync(curatedGraphFile, 'utf-8');
  } catch {
    return 'graph-unreadable';  // permission or I/O error — not fixable by --repair-codegraph
  }
  try {
    JSON.parse(content);
  } catch {
    return 'needs-reinit';  // JSON malformed → --repair-codegraph
  }

  // 3. Dep graph file missing → needs codegraph build
  if (!fs.existsSync(depGraphFile)) return 'needs-graph';

  // 4. Dep graph exists but stale/invalid
  const depGraph = readDependencyGraph(projectRoot);
  const health = checkDependencyGraphHealth(projectRoot, depGraph);
  if (health.status !== 'ok') return 'needs-refresh';

  return 'ready';
}
```

Ghi chú: dùng raw read/parse thay vì `readCuratedCodeGraph` để tránh side effects (stderr logging, exitCode).

## Null-Node Guard in `--check-codegraph`

### Problem

`isTemplateCodeGraph` (codegraph.ts:13) và vòng lặp node trong `runCheckCodeGraph` (codegraph.ts:140) crash với null/non-object input ở hai cấp:

1. **Top-level**: `JSON.parse('null')` → `null`. `isTemplateCodeGraph(null)` reads `null.generated_at` → TypeError crash.
2. **Node-level**: `{"nodes":[null]}` → `JSON.parse` thành công, `isTemplateCodeGraph` và node loop read `null.id` → TypeError crash.

### Behavior phân biệt

| Consumer | Khi gặp null node | Lý do |
|----------|-------------------|-------|
| `readCuratedCodeGraph` / `tryReadCuratedCodeGraph` | `normalizeCuratedGraph` filter ra, normalize an toàn → tiếp tục | compile/try cần chạy được; diagnostic không phải mục đích |
| `runCheckCodeGraph` | Report `invalid`, không crash | `--check-codegraph` là diagnostic tool — schema damage phải nổi rõ |

### Fix 1: Top-level guard trong `runCheckCodeGraph`

Sau `JSON.parse`, trước khi gọi `isTemplateCodeGraph`:

```typescript
if (graph === null || typeof graph !== 'object' || Array.isArray(graph)) {
  console.log(formatStatus('invalid', `.ai/codegraph/graph.json must be a JSON object`));
  console.log('');
  console.log('Result: CodeGraph JSON is invalid.');
  process.exitCode = 1;
  return;
}
```

### Fix 2: `isTemplateCodeGraph` — filter null entries trước khi iterate

```typescript
export function isTemplateCodeGraph(graph: CodeGraph): boolean {
  if (isTodoValue(graph.generated_at) || isTodoValue(graph.source)) return true;
  const nodes = Array.isArray(graph.nodes)
    ? graph.nodes.filter((n) => n !== null && typeof n === 'object' && !Array.isArray(n))
    : [];
  const edges = Array.isArray(graph.edges)
    ? graph.edges.filter((e) => e !== null && typeof e === 'object' && !Array.isArray(e))
    : [];
  return (
    nodes.some((n) => isTodoValue(n.id) || isTodoValue(n.path) || isTodoValue(n.type) || isTodoValue(n.summary)) ||
    edges.some((e) => isTodoValue(e.from) || isTodoValue(e.to) || isTodoValue(e.kind) || isTodoValue(e.summary))
  );
}
```

### Fix 3: Node/edge loops trong `runCheckCodeGraph` — null/type guard

```typescript
for (const [index, node] of nodes.entries()) {
  if (node === null || typeof node !== 'object' || Array.isArray(node)) {
    failures += 1;
    console.log(formatStatus('invalid', `node[${index}] is not an object`));
    continue;
  }
  // ... existing checks unchanged ...
}
```

Tương tự cho edge loop. Không normalize — preserved diagnostic accuracy là mục đích của `--check-codegraph`.

## Shared Normalizer Architecture

`normalizeCuratedGraph` hiện được định nghĩa và export từ `try.ts`. Phase này move nó sang `context-pack.ts` (cùng module với `readCuratedCodeGraph`) và dùng nó ở 3 chỗ:

### Move `normalizeCuratedGraph` → `context-pack.ts`

Export từ `context-pack.ts` thay vì `try.ts`. `try.ts` import lại từ `context-pack.js`.

### Private `parseCuratedCodeGraph` shared bởi cả hai readers

`tryReadCuratedCodeGraph` (context-pack.ts:415–423) có đường read riêng, raw cast — không phải wrapper của `readCuratedCodeGraph`. Cả hai cần được refactor để dùng chung một private function với **discriminated return type** (để `readCuratedCodeGraph` giữ được error detail):

```typescript
type ParseCuratedResult =
  | { ok: true; graph: CodeGraph }
  | { ok: false; error: unknown };

// Private — shared by both exported readers
function parseCuratedCodeGraph(graphPath: string): ParseCuratedResult {
  try {
    return { ok: true, graph: normalizeCuratedGraph(JSON.parse(fs.readFileSync(graphPath, 'utf8'))) };
  } catch (error) {
    return { ok: false, error };  // JSON.parse or fs error; normalizeCuratedGraph never throws
  }
}

export function readCuratedCodeGraph(repositoryRoot = root): CodeGraph | null {
  const graphPath = path.join(repositoryRoot, '.ai', 'codegraph', 'graph.json');
  if (!fs.existsSync(graphPath)) {
    console.error('Error: .ai/codegraph/graph.json not found. Run forgeai-init first.');
    process.exitCode = 1;
    return null;
  }
  const result = parseCuratedCodeGraph(graphPath);
  if (!result.ok) {
    console.error(`Error: .ai/codegraph/graph.json is invalid (${getErrorMessage(result.error)}).`);
    process.exitCode = 1;
    return null;
  }
  return result.graph;
}

export function tryReadCuratedCodeGraph(repositoryRoot: string): CodeGraph | null {
  const graphPath = path.join(repositoryRoot, '.ai', 'codegraph', 'graph.json');
  if (!fs.existsSync(graphPath)) return null;
  const result = parseCuratedCodeGraph(graphPath);
  return result.ok ? result.graph : null;
}
```

`ParseCuratedResult` là private type (không export). `parseCuratedCodeGraph` trả `{ ok: false, error }` chỉ khi JSON.parse hoặc fs.readFileSync throw. `normalizeCuratedGraph` không bao giờ throw — nên `ok: true` là đảm bảo khi parse thành công.

### Tại sao `detectCtaState` tách read/parse nhưng readers không cần tách

Readers (`readCuratedCodeGraph`, `tryReadCuratedCodeGraph`) dùng `parseCuratedCodeGraph` — nếu read hoặc parse fail đều trả `{ ok: false }` → caller nhận `null`. Với compile/try, cả hai fail cases đều có nghĩa "không dùng được graph, fallback về empty" — không cần phân biệt nguyên nhân.

`detectCtaState` cần tách vì CTA khác nhau: read fail → `graph-unreadable` (check permission), parse fail → `needs-reinit` (run repair). Nếu gộp, CTA cho read-fail sẽ trỏ tới `--repair-codegraph` mà command đó từ chối thực thi khi `readFileSync` fail.

Schema-invalid-but-parseable graphs (`{"nodes":[null]}`) được `normalizeCuratedGraph` xử lý an toàn ở reader layer — `detectCtaState` không cần validate schema, chỉ cần biết "read được không?" và "parse được không?".

### Callers sau khi thay đổi

| Caller | Trước | Sau |
|--------|-------|-----|
| `readCuratedCodeGraph` | raw JSON.parse cast | `parseCuratedCodeGraph` (normalize bên trong) |
| `tryReadCuratedCodeGraph` | raw JSON.parse cast | `parseCuratedCodeGraph` (normalize bên trong) |
| `runTry()` in `try.ts` | `normalizeCuratedGraph(tryReadCuratedCodeGraph(...))` | `tryReadCuratedCodeGraph(root) ?? normalizeCuratedGraph(null)` |
| `detectCtaState` | single try/catch over readFileSync+JSON.parse | separate try/catch: read fail → `graph-unreadable`, parse fail → `needs-reinit` |

**Tại sao `runTry()` không dùng `tryReadCuratedCodeGraph(...)` trực tiếp:** `tryReadCuratedCodeGraph` trả `CodeGraph | null`. `null` khi file missing, unreadable, hoặc malformed — đây là các trạng thái mà `try` phải tiếp tục chạy để in CTA đúng. Fallback về `normalizeCuratedGraph(null)` → `{ nodes: [], edges: [] }` → selection trả về rỗng → `formatTryOutput` in đầy đủ report với CTA state tương ứng.

## Testing

### Unit tests (try.test.ts)

**`buildTryReport`:**
- `totalSourceBytes === 0` khi dep graph rỗng
- `totalSourceBytes` = sum của tất cả node sizes qua `fileSizer` (không chỉ selected nodes)
- `totalSourceBytes >= selectedSourceBytes` (selected là subset)

**`formatTryOutput` — exclusion metric:**
- Hiển thị dòng `of ... indexed source (89% excluded)` khi `totalSourceBytes > 0`
- **Không ẩn** khi `selectedSourceBytes === totalSourceBytes` — hiển thị `(0% excluded)`
- Không hiển thị khi `totalSourceBytes === 0`
- Percentage clamped [0, 100] khi fileSizer trả về inflated size

**`formatTryOutput` — CTA states:**
- `ctaState = 'uninitialized'` (default): chứa cả 3 commands (profile, refresh, compile)
- `ctaState = 'graph-unreadable'`: chứa "cannot be read" và "permission"; không chứa `--repair-codegraph`; không chứa `--profile auto`
- `ctaState = 'needs-reinit'`: chứa `--repair-codegraph`; chứa "corrupted"; không chứa `--profile auto`; không chứa `--refresh-codegraph`; không chứa `--upgrade`
- `ctaState = 'needs-graph'`: chứa `--refresh-codegraph`, không chứa `--profile auto`
- `ctaState = 'needs-refresh'`: chứa `--refresh-codegraph` và "stale or invalid" message
- `ctaState = 'ready'`: chứa `--compile-context`, không chứa `--refresh-codegraph`

### E2E tests (dist.test.ts)

**`try` output:**
- Repo với source files: output chứa `% excluded`
- Repo không có source files: output không chứa dòng `Selected ... of`

**`try` CTA state detection (filesystem setup per test):**
- Không có `graph.json`: CTA chứa `--profile auto` (uninitialized)
- `graph.json` is a directory (mkdir instead of file): `readFileSync` throws EISDIR cross-platform → state `graph-unreadable`; CTA chứa "cannot be read" và "read permission"; không chứa `--repair-codegraph`. Dùng thay cho `chmod 000` vì `chmod` không ổn định trên Windows hoặc khi chạy bằng privileged user
- `graph.json` malformed (bất kể manifest state): state `needs-reinit`; CTA chứa `--repair-codegraph` và "corrupted"; không chứa `--profile auto`; không chứa `--upgrade`
- `graph.json` schema-invalid (`{"nodes": [null]}`), dep graph present and fresh (run `--refresh-codegraph` in fixture first): CTA ra `ready` (normalized bởi `parseCuratedCodeGraph`); E2E xác nhận compile sau đó không crash
- `graph.json` valid, dep graph không có: CTA chứa `--refresh-codegraph`, chứa "Build the codegraph"
- `graph.json` valid, dep graph malformed JSON: CTA chứa `--refresh-codegraph`, chứa "stale or invalid"
- `graph.json` valid, dep graph valid: CTA chứa `--compile-context`

**`--repair-codegraph` unit tests (dùng temporary filesystem fixture — không đụng package assets):**

**Test isolation requirement:** Mỗi test phải save và restore toàn bộ shared state trước/sau khi chạy `runRepairCodeGraph`, bất kể test pass hay fail (dùng `try...finally` hoặc một helper như `captureRepair`):
- `process.exitCode` — `runRepairCodeGraph` đặt exitCode 1 cho failure; nếu không restore, test sau sẽ kế thừa exitCode sai
- `fs` mocks (`mock.method`) — phải gọi `mockHandle.mock.restore()` trong `finally` trước khi assert trên filesystem
- `console.log` / `process.stderr.write` — phải restore về hàm gốc trong `finally`
- Temp fixture directory — phải `fs.rmSync(dir, { recursive: true, force: true })` trong `finally`

Recommended pattern: một helper `captureRepair(fn)` nhận callback, capture cả stdout/stderr/exitCode, và restore tất cả trong `finally` của chính nó. Tests dùng `captureRepair` cho I/O isolation; outer `try...finally` chỉ cleanup temp directory; inner `try...finally` (nếu có mock) restore mock trước khi assert trên fs state.

- Read failure: dùng `mock.method(fs, 'readFileSync', ...)` (Node.js built-in test mocking, available since 18.13) để throw EACCES cho canonical graph path; restore after test → exit 1, stderr chứa "could not read", no repair performed, canonical content unchanged
- Parse failure → repair: read succeeds with malformed content → repair proceeds; these are distinct code paths (not the same catch block)
- Template missing: inject nonexistent `templateGraphPath` + malformed `graphPath` in tmp dir → exit 1, stderr chứa "repair failed", canonical unchanged, no tmp left behind, backup may remain (intentional — usually ignored by `.gitignore`; if the gitignore warning appeared, check `git status` before committing)
- Backup collision retry: pre-create `graph.json.backup.X` in fixture dir; inject `randomSuffix` returning `['X', 'X', 'Y', ...]` (first two calls return 'X', third returns 'Y') → first two backup iterations hit EEXIST on pre-created file, third succeeds with `.backup.Y`; repair exits 0
- Backup retry exhaustion: pre-create `graph.json.backup.X`; inject `randomSuffix` always returning 'X' → all 10 attempts hit EEXIST → exit 1, stderr chứa "could not create unique backup path after 10 attempts"
- Tmp collision retry: pre-create `graph.json.tmp.X` in fixture; inject `randomSuffix` returning `['Y', 'X', 'X', 'Z', ...]` (backup uses call 1 = 'Y' and succeeds; tmp uses calls 2–4: 'X', 'X' hit EEXIST on pre-created tmp, then 'Z' succeeds) → repair exits 0
- Tmp retry exhaustion: pre-create `graph.json.tmp.X`; inject `randomSuffix` returning `['Y', 'X', 'X', ...]` (backup uses 'Y' and succeeds; tmp always returns 'X', all 10 hit EEXIST) → exit 1, stderr chứa "could not create unique tmp path after 10 attempts"
- Template read failure (separate from parse failure): `copyFileSync` must succeed (so `tmpPath` exists) before `readFileSync(tmpPath)` can throw. Use `mock.method(fs, 'readFileSync', (p, enc) => { if (p === tmpPath) throw Object.assign(new Error('EIO'), { code: 'EIO' }); return originalReadFileSync(p, enc); })` — mock only the tmp-path read while letting canonical-graph and gitignore reads pass through → exit 1, stderr chứa "could not read template copy", canonical unchanged, tmp cleaned up. Note: `tmpPath` is known only at runtime; test must capture it (e.g., by observing the fixture dir for `.tmp.*` files after a partial run, or by controlling `randomSuffix` to predict the path)
- Template malformed: inject `templateGraphPath` pointing to a file containing invalid JSON → exit 1, stderr chứa "not valid JSON", canonical unchanged, tmp cleaned up, backup may remain (intentional — usually ignored by `.gitignore`; if the gitignore warning appeared, check `git status` before committing)
- Gitignore written: run repair on tmp fixture → `.gitignore` chứa `graph.json.backup.*` và `graph.json.tmp.*`
- Gitignore idempotent: run repair on tmp fixture → write malformed to graph again → run repair again → `.gitignore` không có duplicate patterns (re-malform required so second call reaches gitignore logic)
- Gitignore write failure: inject `gitignorePath` with a nonexistent parent directory (ENOENT on writeFileSync, stable cross-platform) → stderr chứa "Warning: could not write .gitignore", repair still completes (exit 0, canonical repaired)
- Error message format: all operational errors produce `stderr` with `getErrorMessage`, no raw stack trace

**`--repair-codegraph` E2E (CLI command — dùng real assets, không mutate template):**
- Malformed → repair → ready (full lifecycle): run `--profile auto` trong fixture dir (tạo `graph.json` và harness files) → add source files → run `--refresh-codegraph` (build dep graph từ fixture's own source) → write malformed content vào `graph.json` → run `--repair-codegraph` → exit code 0, `graph.json` valid JSON, backup exists → run `try` → CTA `ready`
- Backup uniqueness: write malformed → repair → write malformed again → repair again → verify hai backup files tồn tại với tên khác nhau
- Valid graph refused: setup valid `graph.json` → run `--repair-codegraph` → exit code 0, stdout chứa "already valid JSON — nothing to repair", `graph.json` content unchanged
- No `graph.json`: run `--repair-codegraph` → exit code 1, stderr chứa "nothing to repair", `graph.json` không được tạo
- Manifest untouched: setup malformed `graph.json` + valid `manifest.json` → run `--repair-codegraph` → `manifest.json` content unchanged

**`try` với malformed/missing curated graph:**
- Malformed `graph.json`: `try` in đầy đủ report (Detected, Relevant, Included files) + CTA chứa `--repair-codegraph`; process không crash
- Missing `graph.json`: `try` in đầy đủ report + CTA chứa `--profile auto`; process không crash

**`--check-codegraph` với invalid top-level và null nodes:**
- `graph.json = null`: exit non-zero, stdout chứa `invalid` và "must be a JSON object"; không crash với TypeError
- `graph.json = []`: exit non-zero, stdout chứa `invalid` và "must be a JSON object"
- `graph.json = 42`: exit non-zero, stdout chứa `invalid` và "must be a JSON object"
- `graph.json = {"nodes":[null],"edges":[],...}`: exit non-zero, stdout chứa `invalid` và "is not an object"; không crash với TypeError

**CLI contract (`--help` và override guard):**
- `--help` output chứa `--repair-codegraph`
- `--repair-codegraph --outcome pass` → stderr chứa override guard error (repair is in `commandsBeforeEvaluate`)

**`--compile-context` (file-output mode):**
- Với `--output`: output chứa `source scope`
- Không có `--output` (JSON stdout): output là pure JSON, không chứa `source scope`

## Explicit Constraints

- **Không dùng "token savings"** — chỉ dùng "excluded" (bytes). Product Principle #5.

- `detectCtaState` không export — internal to `try.ts`.
