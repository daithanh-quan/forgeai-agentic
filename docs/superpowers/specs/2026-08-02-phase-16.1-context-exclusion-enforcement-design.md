# Phase 16.1 — Profile context-exclusion enforcement (design)

Date: 2026-08-02
Status: **proposed**
Target release: **3.11.0**

## Scope

This is one of the two items deferred from Phase 16: turn each profile's documented
`## Context exclusion hints` into an enforced boundary for `--context-pack`,
`--compile-context`, and subsequent `--expand-context` requests. The other deferred
item—profile-registered language-specific dependency parsers—is explicitly out of
scope and may be designed independently.

## Problem

Six profiles currently document exclusions: `go`, `rust`, `fastapi`, `django`,
`react-native`, and `sveltekit`. The hints name generated artifacts, migrations,
caches, secrets, and build output such as `*.pb.go`, `alembic/versions/`,
`migrations/`, `.env`, and `target/`.

Today the hints are prose only. Profile-aware commands do not read them, so any
matching file that is present in a dependency graph can be selected or requested in
an expansion. That makes the documented boundary misleading.

The current dependency graph indexes only JavaScript and TypeScript extensions and
already ignores `.next`, `build`, `dist`, `node_modules`, `vendor`, `coverage`,
`.nuxt`, `.output`, `.ai`, and `.git`. Consequently, rules such as `*.pb.go`,
`*.pyc`, and `.env` cannot enter today's graph-backed compiler. They are still kept
as profile policy for documentation drift protection and future parser support, but
the immediate, testable enforcement surface is JS/TS content in directories such as
`migrations/`, `android/`, `ios/`, and `**/tests/fixtures/**`.

## Goals

- Make profile exclusions deterministic, auditable, and enforced by default.
- Apply the same policy to initial selection and later context expansion.
- Preserve the effective profile and override policy in compiled artifacts.
- Ensure excluded nodes do not consume the selection's `max_nodes` allowance.
- Keep old schema-version-1 compiled artifacts readable.

## Non-goals

- A dependency-parser registry or support for indexing Go, Rust, or Python source.
- A second filter during dependency-graph construction. Profile exclusions remain a
  runtime, profile-aware policy.
- Filtering mandatory `.ai/RULES.md` sections or diagnostic metadata. Rules are a
  safety input, and diagnostics contain paths/counts rather than source contents.
- A new general-purpose glob engine. The existing `globMatches` implementation is
  moved unchanged to `path-glob.ts` and re-exported from `context-pack.ts`, avoiding
  a circular import with the pure exclusion module.
- A global switch that disables every exclusion.

## Decisions

1. **Code is the enforcement source of truth.** Profile Markdown remains the
   human-facing source, with a drift test keeping both representations identical.
2. **Exclusions are hard by default.** Objective keyword matching is heuristic and
   is not an escape hatch—otherwise an excluded `.env`-like path could be admitted
   merely because a task mentions environment configuration.
3. **Overrides must be explicit.** A path is kept only when it matches a
   repo-relative glob supplied through `--include-excluded`.
4. **Filtering happens during graph selection.** Excluded seeds and neighbors are
   recorded but are never inserted into the selected set, queue, or node count.
   Traversal does not cross an excluded node.
5. **Expansion inherits policy.** `--expand-context` validates resolved file,
   test, and symbol paths against the primary artifact's policy. It may add an
   explicit `--include-excluded` override for that expansion.
6. **The effective policy is persisted.** Compiled artifacts record active profiles
   and include globs so later expansion and audit do not depend silently on mutable
   manifest state.

## Architecture

```text
bin/lib/profile-exclusions.ts   NEW: pure policy table, normalization, resolution,
                                     matching, and CLI-value parsing
bin/lib/path-glob.ts            NEW: extracted existing globMatches implementation;
                                     context-pack keeps a compatibility re-export
bin/lib/context-pack.ts         EDIT: exclusion-aware seed/traversal selection and
                                     omitted Markdown reporting
bin/lib/context-compiler.ts     EDIT: policy snapshot + omitted entries in primary
                                     and expansion artifacts
bin/lib/context-expansion.ts    EDIT: reject excluded requests before compilation;
                                     record a profile_excluded context escape
bin/lib/context-escapes.ts      EDIT: accept the new escape reason code
bin/lib/context.ts              EDIT: validate --include-excluded as a value flag
bin/lib/router.ts               EDIT: validate new fields when present and normalize
                                     legacy artifacts after estimate verification
bin/lib/types.ts                EDIT: policy, omission, and escape-reason types
```

`profile-exclusions.ts` stays free of filesystem and process access. Command entry
points read the manifest and pass its profile string into the pure resolver.

## Data model

```ts
export type ProfileExclusionRule = {
  pattern: string;          // authored token, e.g. "migrations/"
  reason: string;
};

export type ResolvedExclusionRule = ProfileExclusionRule & {
  profiles: string[];       // sorted contributors after composite deduplication
};

export type ContextExclusionPolicy = {
  profiles: string[];              // normalized components, sorted and deduped
  include_globs: string[];         // normalized repo-relative CLI overrides
  rules: ResolvedExclusionRule[];  // exact policy snapshot used by this artifact
};

export type OmittedContextEntry = {
  path: string;
  pattern: string;
  profiles: string[];
  reason: string;
};
```

`DependencyContextSelection` gains `omitted: OmittedContextEntry[]`.
`CompiledContextArtifact` gains:

```ts
context_exclusions: ContextExclusionPolicy;
omitted_context: OmittedContextEntry[];
```

New artifacts always emit both fields. Schema version remains `1` because the
fields are additive. `checkArtifactStructure` accepts their absence on legacy
artifacts, validates their complete shape when present, and `validateArtifact`
normalizes missing fields to `{ profiles: [], include_globs: [], rules: [] }` and
`[]` only after verifying the historical token estimate.

Omitted entries are deduplicated by path. If several patterns match, choose the most
specific rule (more path segments, then longer pattern, then lexical order). Every
array in the policy and omission data is sorted for deterministic JSON and Markdown.

## Exclusion table

The code table mirrors the Markdown exactly:

| Profile | Patterns | Status |
| --- | --- | --- |
| `go` | `vendor/`, `*.pb.go`, `*_mock.go` | existing hints |
| `rust` | `target/`, `**/tests/fixtures/**` | existing hints |
| `fastapi` | `alembic/versions/`, `__pycache__/`, `.env`, `*.pyc` | existing hints |
| `django` | `migrations/`, `__pycache__/`, `.env`, `staticfiles/`, `media/` | existing hints |
| `react-native` | `android/`, `ios/`, `node_modules/`, `.expo/` | existing hints |
| `sveltekit` | `.svelte-kit/`, `build/`, `node_modules/` | existing hints |
| `python-api` | `__pycache__/`, `.env`, `*.pyc`, `.venv/`, `venv/` | new hints |
| `mobile` | `android/`, `ios/`, `.expo/` | new hints |
| `tauri` | `src-tauri/target/`, `target/` | new hints |

`nextjs`, `node-api`, and `monorepo` receive no profile rule because no
non-redundant exclusion has been identified. Graph-level ignored directories still
apply to them.

Shared patterns across a composite are grouped into one resolved rule with all
contributing profiles. Conflicting reasons for the same pattern are rejected by a
unit/drift test rather than silently choosing one.

## Markdown contract and drift test

Convert every exclusion section to one machine-checkable bullet per rule:

```markdown
## Context exclusion hints

- `vendor/` — vendored dependencies
- `*.pb.go` — generated protobuf source
- `*_mock.go` — generated mocks
```

The drift test parses only bullets matching ``- `<pattern>` — <reason>`` within that
section. It asserts pattern and reason equality in both directions for every profile
in the code table. A profile without a table must not contain the section. This is
less fragile than collecting every backticked token from prose.

## Pattern semantics

Authored profile patterns are shorthand. `normalizePatternToGlobs(raw)` expands
them for the existing anchored `globMatches` implementation:

| Authored form | Concrete globs |
| --- | --- |
| `vendor/` | `vendor/**`, `**/vendor/**` |
| `alembic/versions/` | `alembic/versions/**`, `**/alembic/versions/**` |
| `*.pb.go` | `*.pb.go`, `**/*.pb.go` |
| `.env` | `.env`, `**/.env` |
| `**/tests/fixtures/**` | unchanged |

All candidates are normalized to repo-relative POSIX paths before matching.
Authored patterns reject absolute paths, `.`/`..` segments, and empty values at
module-test time.

`--include-excluded` values are actual globs, not shorthand. The CLI accepts one
comma-separated value, trims entries, removes duplicates, and rejects empty entries,
absolute paths, and `.`/`..` segments. It is added to the eager value-flag validation
in `context.ts`, so bare and repeated uses fail consistently with other value flags.

Matching order is:

1. Any include glob matches → keep.
2. Otherwise select the most-specific matching resolved exclusion rule → omit.
3. No match → keep.

## Active-profile discovery

Command entry points call `readManifestResult()` and:

1. On a valid manifest, normalize and split `manifest.profile` with
   `parseCompositeProfile`.
2. Retain structurally valid, available components in the policy snapshot (including
   profiles that currently contribute no rules), then union rules for table-backed
   components and dedupe as described above. The special `base` profile resolves to
   an empty policy.
3. On a missing manifest, use an empty policy.
4. On an invalid manifest or non-string profile field, write one warning to
   **stderr** and use an empty policy. This avoids corrupting JSON written by
   `--compile-context` to stdout.

Malformed/unknown profile components in an otherwise readable legacy manifest do
not make context commands fail; they contribute no rules and are named in the stderr
warning. `--check-profile` remains the strict validation surface.

## Selection enforcement

`selectContextForObjective` accepts resolved rules and include globs in
`ContextPackOptions`.

- Filter seed candidates before they enter the selected map.
- For every graph neighbor, check the path before adding it to `selected` or the
  traversal queue.
- Record each encountered excluded path once in `omitted`.
- Do not count omitted paths toward `max_nodes` and do not traverse through them.
- Derive curated nodes, contracts, and entrypoints only from kept paths.

This placement is important: filtering the finished selection would let excluded
nodes consume the bound and could prevent an allowed sibling from being selected.

`buildContextPack` adds:

```markdown
## Omitted by Profile Exclusion

| Path | Pattern | Reason | Profiles |
| --- | --- | --- | --- |
| src/migrations/0001.ts | migrations/ | generated migrations | django |
```

An empty list renders `- none`.

## Compiler and expansion enforcement

Primary compact and baseline compilation both consume the filtered selection, so
their excerpts cannot contain omitted graph paths. There is no separate rule-source
filter: current compiled rules always come from mandatory `.ai/RULES.md`, and every
source excerpt comes from graph selection.

The primary artifact stores the effective policy and the selection's omissions.
Markdown renders the same omission table as context-pack.

For `--expand-context`:

- New primary artifacts supply the saved profiles **and resolved rules**, so an
  installed CLI/profile-table update cannot silently change expansion policy.
  Legacy primaries resolve the current manifest policy once and persist it on the
  expansion artifact.
- Expansion-level `--include-excluded` globs are unioned with the saved overrides.
- `validateNeedContext` applies exclusions after resolving file/test/symbol paths
  and before returning valid requests.
- Rejected paths use the new `profile_excluded` escape reason and name the matching
  pattern/profile in the detail.
- A symbol resolving to both kept and excluded paths keeps the allowed paths and
  records one escape for each excluded resolution.
- The expansion artifact contains its own effective policy and omitted entries.

This closes the bypass where an excluded path could be requested after a clean
primary compile.

## Compatibility and validation

- No manifest schema change.
- Compiled-context `schema_version` stays `1`; both new fields are additive.
- Router structure validation checks canonical repo-relative omission paths,
  non-empty patterns/reasons/profiles, valid resolved rules, sorted uniqueness,
  dependency-graph membership, and that an omitted path does not also appear in
  `selection.files` or `excerpts`.
- Context-pack output is Markdown and remains backward compatible.
- Token estimates are computed after policy and omission metadata are present.
- Old artifacts are estimate-checked in their original wire shape before defaults
  are attached, matching the existing compatibility convention.

## Testing

### Unit

- Pattern normalization: root/nested directories, filename globs, dotfiles, and an
  already-recursive glob; Windows separators normalize to POSIX.
- Pattern validation rejects empty, absolute, and traversal patterns.
- Matching: exclusion, explicit include override, no match, and specificity.
- Composite resolution: union, contributor aggregation, stable ordering, and
  conflicting-reason rejection.
- CLI parsing: bare, repeated, whitespace, empty comma member, traversal, and valid
  comma-separated include globs.

### Drift

- Each code-table profile has exactly the same pattern/reason bullets in Markdown.
- A profile without code rules has no exclusion section.

### Selection and context-pack

- A `django` graph with `src/migrations/0001.ts` as a seed omits it by default.
- An excluded neighbor does not consume `max_nodes`; an allowed sibling can still
  be selected.
- Selection does not traverse through an excluded node.
- `--include-excluded "**/migrations/**"` keeps the node.
- Composite profile rules are unioned and omission output is deterministic.

Use JS/TS fixtures for integration tests because that is the graph's current source
surface; keep Go/Python/Rust extension matching in pure unit tests until parser
support exists.

### Compiler, compatibility, and expansion

- Compact and baseline artifacts omit matching selection/excerpt paths and record
  `context_exclusions` plus `omitted_context`.
- Markdown renders omissions.
- An expansion request for an excluded file/test is rejected and recorded as
  `profile_excluded`.
- A symbol with mixed allowed/excluded resolutions partially succeeds and records
  the excluded resolution.
- An expansion-level include glob permits the requested path and is persisted.
- Legacy artifacts lacking both fields still validate with their historical token
  estimate and receive safe defaults.
- Router rejects malformed, duplicate, unsorted, or contradictory omission data.
- Repeated runs produce byte-identical policy and omission arrays.

## Follow-up

The language-parser registry remains separate. When it adds Go, Rust, or Python
nodes, these existing profile policies begin protecting those files without changing
the matching contract or artifact schema.
