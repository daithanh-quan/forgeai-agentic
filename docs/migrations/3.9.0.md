# Migration Guide — 3.9.0

## What changed

Phase 13A adds structured evaluation records and an aggregate report. This is an
**additive** release — no breaking config or schema changes.

- **`--evaluate --task <id>`.** Builds one structured evaluation record for a
  task by joining its review scorecard, task journal, run records, and
  compiled-context artifact by `task_id`. The outcome is derived from the review
  `Verdict` (`approve→pass`, `request changes→fail`, `needs human
  decision→partial`). A strict consistency gate rejects contradictory or
  incomplete inputs and writes nothing on failure. Records are written to
  `.ai/state/evaluations/<task_id>.json`.

- **`--report [--json]`.** Aggregates evaluation records by model tier (pass
  rate, total/mean token cost, mean latency, retries). `--json` emits the
  aggregate object for CI.

- **`task_id` linkage.** `--compile-context --task <id>` stamps `task_id` and
  `artifact_role` (`primary` / `expansion`) into the compiled-context artifact,
  and `--route` copies `task_id` into the run record. These are additive
  (`schema_version` stays `1`). Artifacts and run records written before 3.9.0
  lack the fields and are read as `task_id: null` / `artifact_role: 'primary'`.
  They are not retro-evaluated — only tasks compiled/routed with a `--task` id on
  3.9.0+ produce linked evaluation data.

- **`--check-evaluation` deprecated (soft).** The manual `.ai/evaluation/*.md`
  system still validates and passes/fails as before, but now prints a one-line
  notice pointing to `--evaluate` / `--report`. No files are removed.

## How to migrate

```bash
forgeai-init --upgrade
```

Evaluation records under `.ai/state/evaluations/` are gitignored (local derived
state) and preserved on upgrade. No changes are required to existing run records,
compiled-context artifacts, adapters, or the manual evaluation files.
