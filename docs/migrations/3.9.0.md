# Migration Guide — 3.9.0

Phase 13 — structured evaluation, context experiments, and context-escape
measurement. This is an **additive** release: no breaking config or schema
changes, and `schema_version` stays `1` everywhere. Data written by earlier 3.x
versions reads back with safe defaults.

## How to migrate

```bash
forgeai-init --upgrade
```

Evaluation records (`.ai/state/evaluations/`) and the context-escape store
(`.ai/state/context-escapes/`) are gitignored local derived state and preserved
on upgrade. No changes are required to existing run records, compiled-context
artifacts, adapters, or the manual evaluation files.

## What changed

### Structured evaluation (13A)

- **`--evaluate --task <id>`** builds one evaluation record per task by joining
  its review scorecard, journal, run records, and compiled-context artifact by
  `task_id`. The outcome is derived from the review `Verdict`
  (`approve→pass`, `request changes→fail`, `needs human decision→partial`). A
  strict consistency gate rejects contradictory or incomplete inputs and writes
  nothing on failure. Records go to `.ai/state/evaluations/<task_id>.json`.
- **`--report [--json]`** aggregates evaluation records by model tier.
- **`task_id` linkage**: `--compile-context --task <id>` stamps `task_id` and
  `artifact_role` into the artifact; `--route` copies `task_id` into the run
  record. Artifacts/records written before 3.9.0 lack the fields and read as
  `task_id: null` / `artifact_role: 'primary'`; they are not retro-evaluated.
- **`--check-evaluation` deprecated (soft)**: the manual `.ai/evaluation/*.md`
  system still validates but prints a notice pointing to `--evaluate` /
  `--report`. No files are removed.

### Context experiments (13B)

- `--compile-context` accepts `--mode baseline|compact` (default `compact`, the
  prior behavior) and `--experiment <EXP-YYYYMMDD-slug>`.
- Compiled-context artifacts and evaluation records gain `mode` and
  `experiment_id`; evaluation records also gain a `comparability` block; run
  records gain `mode`.
- `--evaluate` enforces an experiment provenance gate (only when the artifact is
  part of an experiment).
- `--report` gains an Experiments section, a `--min-samples <n>` override, and an
  advisory recommendation; `--report --json` gains `experiments` and
  `recommendation`.
- Pre-existing artifacts/records read as `mode: compact`, `experiment_id: null`,
  `comparability: null` and are excluded from experiment pairing.

### Context escapes and expansion lineage (13C)

- **`parent_artifact`** on compiled-context artifacts: `null` for primary
  artifacts, the primary's path for expansion artifacts. Pre-3.9.0 artifacts
  read as `null`.
- **Context-escape store** at `.ai/state/context-escapes/<task_id>/`
  (`observed/<primary_digest>.json` markers + `events/<escape_id>.json`
  records), written by `--expand-context` for every declined `need_context`
  request. Gitignored and preserved on upgrade.
- **`--evaluate`** reports a real `metrics.context.context_escapes`: `null` when
  the evaluated primary was never observed by an `--expand-context` run, `0` when
  observed with no escapes, `N` distinct declined needs otherwise. A malformed
  escape record fails evaluation and writes no record.

## Behavior changes

- `--expand-context` now rejects an expansion artifact as `--artifact`
  (expansion-of-expansion is not supported) and an artifact resolving outside the
  repository root.

## Action required

None. Existing evaluation records, run records, and compiled-context artifacts
remain valid and read with the additive fields defaulted.
